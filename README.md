# Safe HTML Reader for EdgeEver

Safe HTML Reader is a read-only client plugin for [EdgeEver](https://github.com/tianma-if/edgeever). It keeps the note itself as portable Markdown while adding a focused reading panel for a deliberately small, sanitized subset of HTML.

It is designed for bilingual close reading:

- vocabulary such as `<abbr title="中文释义"><strong>word</strong></abbr>` receives a consistent hover, focus, and tap tooltip;
- references such as `<sup>[1]</sup>` can preview and jump to a matching `### [1] Note title` heading;
- standard Markdown, `<mark>`, `<sub>`, `<sup>`, `<u>`, `<details>`, `<summary>`, `<del>`, and `<kbd>` render in a restrained reading layout;
- the original Markdown is never rewritten or converted to an EdgeEver-specific format.

## EdgeEver API contract

The implementation supports both the EdgeEver v1.51.1 Plugin API at official commit `c22437e09dc5f54d6c71896b48a808833615f45e` and the expanded Plugin API v1 at official commit `609a589ebbeb0ed0182fe4f73cdf885b4ed62b74` (2026-09-01).

It uses only these official capabilities:

- `context.commands.register()`
- `context.ui.panels.register()` on all supported versions and `context.ui.panels.open()` when available
- `context.editor.getSelection()` plus `context.notes.get()` on EdgeEver v1.51.1 for the active note's saved Markdown
- `context.editor.getDocument()` on newer builds for the live Markdown, including unsaved changes
- `context.notes.get()` for the saved note title
- `context.ui.showNotice()` for a missing active note

The manifest requests only:

```text
notes:read
editor:read
ui:commands
ui:notices
ui:panels
```

It has no note-write, delete, network, storage, or secret permission.

The current EdgeEver API does not expose custom TipTap/ProseMirror marks or nodes, a per-plugin toolbar button, or an active-note-changed event. Safe HTML Reader therefore leaves the editor untouched, uses the official unified plugin panel entry, and checks the live document at a low frequency only while its panel is open. Newer EdgeEver builds also show a command that opens the panel directly. It reparses only when the note or Markdown changes.

The official `@edgeever/plugin-api` package exists in the EdgeEver monorepo but was not published to npm when version 1.0.0 was built. This project keeps a minimal, type-only declaration of the APIs it actually calls, so the release bundle has no unresolved runtime SDK import.

## Security

The rendering pipeline is:

```text
Markdown source
  -> marked parser
  -> DOMPurify strict tag/attribute allowlist
  -> per-tag attribute and URL validation
  -> sanitized DocumentFragment
  -> reading panel
```

The plugin does not assign untrusted note output to `innerHTML`. It inserts the sanitized `DocumentFragment` and then adds interaction using DOM methods and event delegation.

Allowed HTML includes the requested inline tags plus the ordinary elements generated by Markdown:

```text
abbr sup sub mark strong em u details summary del kbd
h1-h6 p blockquote ul ol li a img pre code hr br table thead tbody tr th td
```

User-supplied scripts, frames, embedded objects, styles, inline styles, `on*` event handlers, `srcdoc`, unknown attributes, and unsafe URL schemes are removed. External links open with `noopener noreferrer`. Tooltip text is assigned with `textContent`, so an `<abbr title>` value is never interpreted as HTML.

Safe HTML Reader follows EdgeEver's trusted-plugin model: installed plugin JavaScript runs in the client page. Install only code and releases you trust.

## Installation

### 1. Clone

```sh
git clone https://github.com/yaqxuan/edgeever-safe-html-reader.git
cd edgeever-safe-html-reader
```

### 2. Install dependencies

```sh
npm install
```

### 3. Build and verify

```sh
npm run check
```

The release-ready files are written to `dist/`:

```text
dist/manifest.json
dist/main.js
dist/styles.css
```

`main.js` is a browser ESM single-file bundle with no relative runtime imports. The build also verifies EdgeEver's 5 MB JavaScript and 1 MB stylesheet limits.

The same three files are kept at the repository root so EdgeEver can also install the plugin from a manifest URL if GitHub's Release asset API is temporarily unavailable or rate limited.

### 4. Create a GitHub Release

Push the repository to a **public** GitHub repository. Keep the latest `manifest.json` at the repository root. Create a release whose tag matches the manifest version, either `1.0.2` or `v1.0.2`, and upload these three files as separate release assets:

```text
dist/manifest.json  -> manifest.json
dist/main.js        -> main.js
dist/styles.css     -> styles.css
```

With GitHub CLI:

```sh
gh release create v1.0.2 \
  dist/manifest.json \
  dist/main.js \
  dist/styles.css \
  --title "Safe HTML Reader v1.0.2" \
  --notes-file RELEASE.md
```

The release `manifest.json` must be byte-for-byte identical to the root manifest for that version.

### 5. Install in EdgeEver

1. Open your EdgeEver instance.
2. Go to `/plugins` or open **Plugin Marketplace** from the unified plugin menu.
3. Paste the public repository URL, for example:

   ```text
   https://github.com/yaqxuan/edgeever-safe-html-reader
   ```

   If EdgeEver reports `GitHub asset manifest.json failed with HTTP 403`, use this manifest URL instead:

   ```text
   https://cdn.jsdelivr.net/gh/yaqxuan/edgeever-safe-html-reader@main/manifest.json
   ```

   This downloads the same checked-in package without using GitHub's Release asset API.

4. Review the five read-only/UI permissions.
5. Install and enable the plugin.
6. Open a note and run **Open Safe HTML Reading View** from EdgeEver's plugin menu.

GitHub installations are marked as unverified unless the plugin is later admitted to EdgeEver's verified marketplace.

## Example

```markdown
# Example Article

This result was <abbr title="令人震惊的；惊人的"><strong>staggering</strong></abbr>.

This is <mark>important</mark>.

这是一个重要的文化背景。<sup>[1]</sup>

## 注释

### [1] 示例注释

这里是第一条注释。
```

A larger sample is available in [`example/Example Article.md`](example/Example%20Article.md).

### Reference format

V1 intentionally uses portable HTML and Markdown:

```markdown
正文。<sup>[1]</sup>

### [1] 注释标题

注释正文。
```

The number inside `<sup>[n]</sup>` is matched to the first Markdown heading whose visible text begins with the same `[n]`. A missing definition leaves the superscript readable and shows a non-fatal “not found” tooltip. A plain numeric superscript such as `<sup>2</sup>` remains a normal superscript.

## Usage

- Hover or keyboard-focus a vocabulary item to read its definition.
- Tap/click a vocabulary item to pin its tooltip; click elsewhere or press Escape to close it.
- Hover/focus a reference to preview the matching note.
- Click a reference to scroll to its definition.
- Use the panel's **刷新** button for an immediate refresh. While open, the panel also follows the current editable note and rerenders only after a change.
- Close the panel with EdgeEver's standard dialog close control.

  main.ts          plugin activation, command, and panel registration
  panel.ts         current-note loading and reading panel lifecycle

## Limitations

- Plugins are installed per device and do not sync through EdgeEver.
- EdgeEver plugins currently run only while the app is open.
- The saved title can briefly lag behind an unsaved title edit because the live editor API exposes Markdown and note ID, but not the live title.
- Custom panels are standard EdgeEver dialogs and cannot yet be pinned to the editor sidebar.
- This is a deliberately limited HTML reader, not a general web browser. Unsupported tags are stripped while their readable text is retained when possible.
